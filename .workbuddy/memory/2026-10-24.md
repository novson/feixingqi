## 项目启动：在线飞行棋（feixingqi）

- 目标：2–8 人在线飞行棋，朋友约局；账号登录模式参考 `E:\user\github_project\poker-game`（无密码账号：昵称 + 跨设备登录码，服务端存 SHA-256，localStorage 存 accountId/accountToken，请求头 X-Account-Token）。
- 与用户确认的三个决策：
  1. 规则 = 经典通用版（掷 6 起飞并可连掷、同色格跳棋、飞机场飞半圈、撞子回库、终点精确点数）。
  2. 房间形态 = 房间制 + AI 补位（掉线/离房自动托管）。
  3. 技术栈 = Node 全栈（本机无 JDK/Maven/Docker，只有 Node 22；poker-game 的 Java 栈无法在本机编译验证）。

## 实现要点

- 棋盘：`TRACK=56` 格外圈（4 人时每边 14 格，四角即起飞点），`HOME_LANE=6`，`FINISH=62`，`HANGAR=-1`。
- 颜色循环着色 `cell % players`，跳棋距离 = 玩家数（4 人即经典 4 格；房间可设 `jumpMode=CLASSIC4` 固定 4 格）。
  - 注意：56 只能被 2/4/7/8 整除，3/5/6 人局在接缝处颜色循环会错一格（跳棋点数量差 ≤1，已测试覆盖）。
- 飞机场 = 起飞点 + 半个区间，飞棋 +28（半圈）后再前进一个同色间距；飞/跳各只触发一次。
- 后端零框架依赖的领域层（`rules.js` / `game.js` / `ai.js` / `rooms.js`），HTTP 与 WS 用 Fastify + @fastify/websocket；房间状态整份广播（飞行棋无隐藏信息）。
- 前端 Vue 3 + Vite，SVG 棋盘（`web/src/services/board.js` 为几何唯一来源）。

## 坑

- 本机 `npm install` 走默认 registry 会卡死 20+ 分钟，换成 `--registry=https://registry.npmmirror.com` 后 6 秒完成。
- `@fastify/static` 注册后再 `app.get('/*')` 会报路由重复，SPA fallback 要用 `setNotFoundHandler`。
- Node 22 的 `node --test test/` 会把目录当模块解析，必须写 `node --test test/*.test.js`。

### 进程管理（用户明确要求）

- 用户问「是不是用 nohup 跑的」，要求全部 systemd + 故障自动重启。远端本来就是 systemd（本机 Windows 那个只是临时预览，已停掉）。
- 单元加固：`Restart=always`（原来是 on-failure，覆盖 SIGKILL/非零退出/干净退出）、`RestartSec=3`、`StartLimitIntervalSec=300` + `StartLimitBurst=10`、`MemoryMax=512M`、`SyslogIdentifier=feixingqi`、`enabled` 开机自启。
- 实测：`kill -9` 主进程 → 3 秒后自动拉起，NRestarts=1，接口恢复，nginx/poker 不受影响。

### nginx 的一个坑

`location /feixingqi/api/ + proxy_pass http://127.0.0.1:18090/;` 会把匹配前缀整段替换，后端收到的是 `/health`；
必须写成 `proxy_pass http://127.0.0.1:18090/api/;`。因为后端 SPA fallback 会把未知路径返回 index.html，
这个错误表现为「接口返回 HTML」而不是 404，容易被误判成前端问题。
